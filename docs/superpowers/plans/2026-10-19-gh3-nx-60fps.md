# gh3-nx — 60 FPS estáveis (render, present e CPU) — Implementation Plan

> **For agentic workers:** tarefas atômicas com aceite local (build + pytest + captura). O teste no Switch é só a Fase 5, como pedido. Checkbox (`- [ ]`) por tarefa.

**Goal:** levar o GH3-nx de ~45 FPS (modo desempenho, clocks de fábrica) para **60 estáveis**, sem religar sombra/bloom, com piso de resolução **0,65** e CAS, mantendo paridade visual e sem piscadas verdes.

**Baseline (medido, playbook §8):** ~45 FPS medianos, GPU 13 ms/quadro, renderer CPU ~13 ms, 8 quadros >50 ms/10 s. Orçamento de 60 FPS: 16,7 ms; meta de trabalho GPU ≤11 ms e renderer CPU ≤10 ms.

**Gate final (Switch, Fase 5):** 3 corridas na mesma música/trecho, clocks de fábrica, overlay fechado; mediana ≥58 FPS, **zero quadros >50 ms** por 10 s, 99º percentil ≤20 ms, sem verde, paridade com o build atual, `check_no_game_content.sh` limpo, suíte verde.

**Decisões:** 60 estáveis; piso 0,65 / teto 1,0; **manter o modo desempenho** (sombra/bloom continuam cortados); investir no SDK/Mesa (spirv-tools + NAK/draw path); testes locais livres, Switch só no fim.

**Não fazer:** ZCULL sem o pacote completo; `vblank late-no-wait` como FPS; baixar resolução sozinho; FP16/VRS no NAK/GM20B; AFBC; depth prepass; occlusion queries; FSR 2; 4º work slot; thread de apresentação; EDS 1/2/3; sombra a cada N frames; culling por bbox sem medir; swap de resolve de cor; religar sombra/bloom.

## Fase 0 — Instrumentação e baseline

- [ ] **F0.1** Protocolo A/B: 3 corridas na mesma música/trecho, mediana, % >50 ms, 1% low, timestamps NVK ×1,627. Ferramenta: `tools/gameplay_fps.py` (+ doc no playbook §8).
- [ ] **F0.2** Log por swap (cvar `gh3_native_swap_log`): frontbuffer, w×h, `VkFormat`, clear, resolve src/dst, RT key, `alias_seq`, fence wait. Arquivos: `src/native/native_renderer.cpp`, `src/native/gh3_native_system.cpp`.
- [ ] **F0.3** Fechar o verde: fallback preto já aplicado; se persistir, present/ownership/formato (ReXGlue #508/#513). Aceite: 10 transições sem verde.
- [ ] **F0.4** Auditoria de formato/clear: logar `VkFormat` por target; 16F sem HDR; gamma; clear repetido.
- [ ] **F0.5** Validar o T24 localmente: profile por passe com o render area da sombra/efeito em 90–360 linhas (não 2048); captura OK.

## Fase 1 — Pixels/GPU (maior alavanca)

- [ ] **F1.1a** `switch/gh3.toml`: `gh3_native_scene_scale = 0.65`. Aceite: log `scene scale 0.65: 832x468`, captura white/stddev, paridade de composição.
- [ ] **F1.1b** Controlador dinâmico 0,65–1,0 com histerese (2–3 frames, passos de 0,05, 0,5–1 s no mesmo nível), alvo 16,7 ms; recriação dos alvos `scene_scaled` ao mudar a escala.
- [ ] **F1.1c** CAS no blit da cena (substituir/complementar o `vkCmdBlitImage` LINEAR); aceite: imagem mais nítida, paridade de composição.
- [ ] **F1.2** Generalizar o cap de render area (T24) para todo alvo inflado (160/320×2048) e para o caminho samples-as-pixels; aceite: nenhum passe de sombra/efeito com altura 2048.
- [ ] **F1.3** Overdraw exato: pular blend `0×src + 1×dst` sem escrita de Z/stencil e alpha test NEVER; `EarlyFragmentTests` só em draws que testam Z sem escrever; front-to-back. Referência: `nfsmw_nativo_dibujos.cpp:918-934,823-857`.
- [ ] **F1.4** Auditoria de formatos: `depth24`, 64bpp, 16F, gamma; eliminar alvo caro sem HDR real.
- [ ] **F1.5** Confirmar 1 sample/alias sem conteúdo velho entre frames.

## Fase 2 — SDK/Mesa e shaders (investimento)

- [ ] **F2.1** Construir `SPIRV-Tools` + `SPIRV-Tools-opt` no Mac e no devkitA64 (patch local no SDK, aplicado pelo `tools/setup_sdk.sh`, como o do Mesa; instalar as libs em `out/sdk-install`).
- [ ] **F2.2** `spirv-opt` nos shaders traduzidos: validar, fallback ao original, contar instruções, logar a cada 10 s `spirv-opt: N shaders, X% fewer instructions (M fallbacks)`. Cvar `gh3_native_spirv_opt` (padrão false; true no Switch).
- [ ] **F2.3** NAK/draw path do nfsmw: latência 200, peephole 8, rebinds de constant buffer (Mesa).
- [ ] **F2.4** Simplificar shaders: remover `max(a,a)`, `textureSize`, fundir branches.
- [ ] **F2.5** Prewarm de pipelines + cache versionado; aceite: zero pipeline novo em gameplay.

## Fase 3 — Resolve, present e frame

- [ ] **F3.1** Instrumentar present/fence do presenter; medir a espera por 10 s (`present fence wait X ms/10 s`).
- [ ] **F3.2** Present ring 3 output slots (1 submit/frame, `IMMEDIATE` no Switch) **se 3.1 justificar**; nunca 4º work slot.
- [ ] **F3.3** Resolve sem cópia só para depth/lazy, com restauração antes de resolver/desenhar e paridade pixel.
- [ ] **F3.4** Contrato de frame (attachment roles, resolves, copies, depth handoff) inspirado no Theft4.

## Fase 4 — CPU do ring e build

- [ ] **F4.1** Caches por draw: `IM_LOAD_IMMEDIATE`, sampler entre frames, query resets seletivos, zero log no ring.
- [ ] **F4.2** Function ordering + `non_volatile_as_local` + A/B `-O2`.
- [ ] **F4.3** PGO representativo (menus + música + vídeo).
- [ ] **F4.4** Funções quentes em C++/NEON (T19) — só se o guest virar o limite a 60; começar pelas menores.

## Fase 5 — Validação final no Switch (única fase com o aparelho)

- [ ] Deploy do NRO/pacote; 3 corridas na mesma música; mediana ≥58, zero >50 ms, 99º ≤20 ms.
- [ ] 10 transições intro→menu→música→menu sem piscadas verdes.
- [ ] Paridade visual com o build atual (modo desempenho + 0,65/CAS).
- [ ] Suíte completa, `check_no_game_content.sh`, playbook/sessão/registro de impacto.

## Ordem e dependências

1. F0 (instrumentação) antes de F3.3/F3.2.
2. F1.1a/F1.2 (pixels) antes de F1.1b/c (dinâmico/CAS).
3. F2.1 antes de F2.2 (spirv-opt).
4. F4.4 só depois de medir o guest a 60.
5. F5 por último, com o pacote congelado.

## Riscos

- Otimizar sem checkpoint no Switch: a Fase 5 pode revelar que o ganho do Mac não transferiu. Mitigação: instrumentação da F0 + profile por passe no Mac.
- A 60 FPS o limite pode virar o **guest/CPU** (não a GPU): nesse caso F4.4 entra no caminho crítico.
- O controlador dinâmico mexe no ciclo de vida dos alvos `scene_scaled`; a recriação precisa preservar o conteúdo (sync) e não piscar.
- O build do spirv-tools no devkitA64 é o item de maior risco de tempo; se falhar, F2.2 fica condicionada.
